# aj-workflow 待修复事项

最后审查日期：2026-08-12

审查范围：`src/main/java`、`src/test/java`、`src/sql/mysql.sql` 和 `pom.xml`。

本轮已完成 ajaxjs-util 1.3.6 API 迁移、Spring 通用工具替换、任务变量和参与者
处理修复、ANY/ALL 任务语义修复、活动/历史实例生命周期修复、流程版本排序、
XML 空输入校验、中文源码注释补充及离线单元测试。以下是仍需处理的问题。

## P0——安全与数据一致性

- [ ] **恢复任务完成时的权限校验。**
  `TaskService.complete()` 中的 `isAllowed(task, operator)` 仍被注释。知道任务 ID 的调用者
  可能绕过参与者限制完成任务。系统自动完成应使用单独的内部入口或明确的系统身份，不能
  依靠 `null` 操作人绕过权限。

- [ ] **为核心状态转换建立事务边界。**
  启动流程、完成任务并创建后续任务、结束流程、撤回、驳回、转派和级联删除均由多个独立
  SQL 操作组成。中途失败会留下活动表、历史表和参与者表不一致的数据。应在同一数据库事务
  中完成整组操作，异常时整体回滚。

- [ ] **防止同一任务被并发完成两次。**
  当前流程是“查询活动任务—写历史任务—删除活动任务”，没有行锁、乐观锁或条件删除。
  两个并发请求可能重复创建历史记录和后续任务。应采用 `SELECT ... FOR UPDATE` 或带版本号
  的条件更新/删除，并检查影响行数实现幂等。

- [ ] **限制动态跳转权限。**
  `executeAndJumpTask()` 可以直接跳到任意已知节点，可能绕过审批、决策和会签。应增加独立
  管理权限、允许目标白名单和完整审计记录。

- [ ] **限制流程 XML 中的反射与表达式能力。**
  XML 可指定拦截器、DecisionHandler、CustomModel 类和方法、回调类及 EL 表达式。若部署
  权限控制不严，会形成服务端任意类实例化或方法调用入口。应将部署限定为管理操作，并对类、
  包、方法和表达式能力建立白名单。

## P1——并发与流程正确性

- [ ] **消除缓存流程模型中的运行期可变状态。**
  `ProcessService` 缓存并复用 `ProcessModel`，执行时却修改 `TransitionModel.enabled` 等字段。
  并发流程实例可能互相污染。流程定义应改为不可变对象，分支是否启用等运行状态应放入
  `Execution`。

- [ ] **修复解析器单例的线程安全问题。**
  `AbstractNodeParser.model` 是实例字段，而 Spring 解析器默认是单例 Bean。并发部署或加载
  流程时可能相互覆盖结果。应让 `parse()` 使用局部变量并直接返回模型，使解析器完全无状态。

- [ ] **补齐流程定义的结构校验。**
  当前没有系统拒绝重复节点名、多个 start、Transition 目标不存在、空名称、不可达节点、
  普通节点无出口和非法循环。应在部署前完成整图校验并给出节点级错误信息。

- [ ] **为流程图遍历增加环检测。**
  `NodeModel.addNextModels()`、Join 反向搜索等递归没有 visited 集合，特定循环图可能导致
  栈溢出。

- [ ] **明确 Decision 的单分支或多分支语义。**
  当前多个条件同时为 true 或多个 Transition 名称相同时会执行多条路径。若 Decision 设计为
  单分支，应在多匹配时拒绝；若支持多分支，应明确文档并避免与 Fork 重复。

- [ ] **完善多实例下的流程版本分配。**
  `deploy()` 的 `synchronized` 仅保护单 JVM；数据库脚本已有 `(name, version)` 唯一索引，
  但代码尚未对唯一键冲突进行重试或转换为清晰的部署冲突异常。

## P1——SQL 与存储

- [ ] **修复并参数化动态 SQL。**
  `WfData.findByOrderIdAndExcludedIds()` 存在缺少 `AND`/空格、直接拼接节点名称、修改调用方
  数组等问题；`findByIdAndExcludedIds()` 直接拼接 ID 列表，空数组会生成非法 `NOT IN ()`。
  应统一生成 `?` 占位符并绑定参数。

- [ ] **统一活动表和历史表的状态模型。**
  目前完成/终止会更新历史表并删除活动实例，但 resume、terminate、cascadeRemove 与查询接口
  仍缺少完整状态机约束。应明确允许的状态迁移并用影响行数验证每次迁移。

- [ ] **校对 MySQL DDL 与 Java 实体字段映射。**
  建表脚本中同时存在 `state/stat`、`order_state`、`task_state`、`expire_time/expireDate`、
  `createDate/create_date` 等不一致命名，需要通过真实数据库集成测试确认 sqlman 映射结果，
  并统一脚本。

## P2——架构与资源管理

- [ ] **重构子流程的伪异步实现。**
  `SubProcessHandler` 每次创建单线程执行器后立即 `future.get()`，没有异步收益，却会丢失
  sqlman 的 ThreadLocal 数据库连接和事务上下文。应删除该分支或接入由应用管理、可传播上下文
  的执行器；捕获中断时恢复线程中断标记。

- [ ] **降低核心引擎对 Spring 和静态数据访问的耦合。**
  模型对象直接访问 `SpringContext`，服务使用字段注入，DAO 为静态 `WfData`。建议引入
  `WorkflowRepository`、扩展解析注册表和构造器注入，使流程模型可在无 Spring 环境中测试。

- [ ] **规范回调和拦截器异常策略。**
  部分拦截器异常只记录日志后继续运行，部分则包装抛出；这会造成流程是否继续不一致。应区分
  必须成功、允许失败和补偿型扩展，并在配置中明确。

- [ ] **收敛公开可变字段。**
  `WorkflowEngine` 的服务依赖、`ProcessService.lastDeployProcessId` 等字段直接公开，容易被外部
  修改。应改为构造器注入、私有 final 字段和只读访问器。

## P2——测试与文档

- [ ] **建立真实数据库集成测试。**
  当前默认执行 13 个离线测试；旧工作流用例依赖未配置的数据库、Spring 容器和部分缺失资源。
  应使用 H2/MySQL Testcontainers 建立独立 integration-test profile，覆盖部署、启动、ANY/ALL、
  Fork/Join、Decision、子流程、撤回、驳回、转派、终止和恢复。

- [ ] **增加并发与故障注入测试。**
  至少覆盖两个线程完成同一任务、并发部署同名流程、历史写入失败、后续任务创建失败和事务回滚。

- [ ] **继续补齐 Lombok 生成访问器的字段级契约。**
  核心类、字段和显式方法已有中文说明，Javadoc doclint 已通过；大量实体访问器由 Lombok 生成，
  后续应进一步说明 null、默认值、枚举持久化形式及集合所有权。
